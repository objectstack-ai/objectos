# Upgrade

ObjectOS should be upgraded like a runtime distribution: pin versions,
roll forward deliberately, and keep the application artifact immutable.

## Version boundaries

There are two independent versions:

| Version | Owner | Rollback method |
|---|---|---|
| ObjectOS image / npm dependencies | This repository | Roll back the container tag or Git release |
| Application artifact (`objectstack.json`) | Application repository / control plane | Roll back the Project Version pointer or restore the previous file |

Do not mutate an artifact in place. Publish or copy a new artifact and
let ObjectOS reload it.

## Docker Compose upgrade

1. Pull or build the new image:

   ```bash
   docker compose -f docker/docker-compose.yml build --pull
   ```

2. Restart:

   ```bash
   docker compose -f docker/docker-compose.yml up -d
   ```

3. Check health:

   ```bash
   docker compose -f docker/docker-compose.yml ps
   curl -f http://localhost:3000/
   ```

## Rollback

For offline mode, restore the previous artifact:

```bash
cp /backup/objectstack.previous.json docker/artifacts/objectstack.json
docker compose -f docker/docker-compose.yml restart objectos
```

For cloud-connected mode, roll back the Project Version pointer in the
control plane. ObjectOS will pick up the previous current artifact on the
next boot or refetch.

## Dependency upgrades

The runtime consumes upstream `@objectstack/*` packages from npm. Upgrade
them in one PR, run:

```bash
pnpm install
pnpm build
```

Then rebuild the Docker image and run the smoke checks from
[Install](/docs/install).
