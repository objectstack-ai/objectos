# ObjectOS

ObjectOS is the customer-hosted runtime for ObjectStack applications. It
loads a compiled `objectstack.json` artifact, boots the ObjectStack
runtime, and serves the application APIs, metadata-driven UI, identity,
permissions, settings, automation, and integration surfaces described by
that artifact.

ObjectOS is designed for the environments customers actually deploy:
private servers, Docker, Kubernetes, private cloud, and air-gapped
networks.

## What ObjectOS is

ObjectOS is the **runtime distribution** of ObjectStack:

- It runs compiled ObjectStack applications.
- It owns the customer-side HTTP runtime.
- It connects to the business database configured for the project.
- It enforces authentication, permissions, row-level access, and field
  security when those capabilities are enabled.
- It exposes platform administration surfaces such as users, roles,
  settings, sessions, audit logs, webhooks, and diagnostics through the
  Setup app.

## What ObjectOS is not

ObjectOS is not the low-code builder, not the control-plane database, and
not the protocol specification. Those belong to the ObjectStack framework
and cloud/control-plane layers.

The boundary is intentional:

| Layer | Responsibility |
|---|---|
| ObjectStack framework | Protocol, kernel, metadata model, drivers, services, plugins, SDKs |
| Control plane | Project authoring, artifact publishing, hostname/project resolution |
| ObjectOS | Customer-hosted runtime that consumes artifacts and serves applications |

In cloud-connected deployments, ObjectOS talks to the control plane over
the Artifact API. It does not require direct access to the control-plane
database.
