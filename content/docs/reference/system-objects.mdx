# System Objects

ObjectOS exposes platform administration through metadata-driven system
objects. Operators usually interact with them through the Setup app.

## Identity

| Object | Purpose |
|---|---|
| `sys_user` | User account |
| `sys_session` | Active session |
| `sys_account` | Linked identity provider account |
| `sys_organization` | Tenant/workspace |
| `sys_member` | User membership |
| `sys_department` | Organization structure |
| `sys_team` | Collaboration group |
| `sys_invitation` | Invitation |
| `sys_api_key` | Programmatic access |

## Security

| Object | Purpose |
|---|---|
| `sys_role` | Role hierarchy |
| `sys_permission_set` | Permission grants |
| `sys_user_permission_set` | Direct user grant |
| `sys_role_permission_set` | Role-based grant |
| `sys_sharing_rule` | Declarative record sharing |
| `sys_record_share` | Direct record share |

## Settings and secrets

| Object | Purpose |
|---|---|
| `sys_setting` | Settings K/V values |
| `sys_setting_audit` | Settings change history |
| `sys_secret` | Secret metadata |
| `sys_user_preference` | User preferences |

## Diagnostics and operations

| Object | Purpose |
|---|---|
| `sys_audit_log` | Audit trail |
| `sys_notification` | Notifications |
| `sys_job` | Job definition |
| `sys_job_run` | Job execution history |
| `sys_email` | Email delivery record |
| `sys_attachment` | Attachment metadata |

## Integrations

| Object | Purpose |
|---|---|
| `sys_webhook` | Webhook configuration |
| `sys_webhook_delivery` | Webhook delivery log, when webhook plugin is enabled |

System objects are implementation details and admin surfaces. Customer
business applications should use domain objects for business data and
system objects for platform administration.
